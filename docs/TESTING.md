# Проверка Life

## Автоматические тесты

Из корня проекта:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тесты не требуют открытого графического окна. Проверяются классические правила, экосистема, наследование, сохранения, визуальные функции, измерения и серии экспериментов.

## Проверка интерфейса

1. Запустите `python main.py`, затем откройте оба режима и несколько поколений.
2. Проверьте зум колесом и перемещение карты **зажатой ПКМ**: клетки не должны стираться.
3. Проверьте смену палитры и отображение данных в 2D и 3D.
4. В разделе «Анализ» нажмите «Серии экспериментов», затем повторите через `Ctrl+E`.
5. Запустите небольшой план: 3 значения, 2 повтора, 10 поколений, запись каждые 3 шага. После завершения должно появиться 6 строк запусков, 3 строки агрегатов, графики по поколениям и доступный экспорт.
6. Запустите второй план, поставьте паузу и продолжите. Отмените серию: приложение должно остаться открытым.
7. В режиме экосистемы проверьте осадки, затем повторите «Копию текущего». Во время серии текущий мир не должен меняться.
8. Экспортируйте итоговый CSV, временные ряды, JSON и Markdown. Сравните итоговые численности с таблицей интерфейса.
9. Проверьте загрузку миров форматов 1–5 и сохранение текущего мира.
10. В экосистеме откройте вкладку «Родословная». Ctrl+ЛКМ по животному должен выбрать его без рисования. Дождитесь движения и рождения потомков, проверьте ID и цепочку предков, скачайте CSV и проверьте столбцы.
11. Сохраните мир с потомками, загрузите его и сравните ID и счётчики линий. Для сохранения v0.6.0 убедитесь, что у текущих животных созданы независимые линии основателей.

Под Linux без графической сессии проверку GUI можно выполнить через `xvfb-run`; отображение системной строки заголовка следует проверить отдельно под Windows 10/11.

## Проверка воспроизводимости

Повторите одинаковую серию с теми же параметрами и seed. При одинаковой версии программы CSV с итогами должен совпадать. Для тестов заранее фиксируйте исходный seed, размер, режим, набор активных процессов и длительность. Изменение одного параметра может поменять последовательность последующих случайных выборов.


## Визуальная проверка v0.8.0

1. Переключите все 8 тем, 10 палитр и 6 способов отрисовки (включая увеличенный масштаб). В режиме экосистемы убедитесь, что формы трёх типов клеток различаются, а в классическом режиме используются только живые/мёртвые клетки.
2. Переключите F6, F7 и F10, затем верните панели. Убедитесь, что выбранная вкладка исследования и состояние мира сохранились.
3. На экране шириной около 1152 px откройте сначала левую, затем правую панель: они должны взаимно скрываться, чтобы по центру оставалось рабочее поле.
4. Переключите «ШКАЛА», включите крупное увеличение и переместите камеру зажатой ПКМ. Подписи координат должны совпадать с клетками и оставаться над картой.
5. В режиме экосистемы проверьте полосу состава популяции после 10 поколений и при пустой карте. Суммарная цветная ширина не должна превышать ширину полосы.
6. Запустите симуляцию и наведите курсор на график истории. Подсказка должна показывать поколение и численность; переключение режима не должно вызывать ошибки.
7. Закройте и снова откройте приложение: тема, стиль, шкала и заливка графика должны сохраниться.
8. Сохраните и откройте мир `.lifelab` версии 5, сравните численность, RNG и родословные. Для Windows 10/11 дополнительно вручную проверьте системную строку заголовка — она зависит от DWM и системной темы.
9. Для проверки без графической сессии в Linux используйте `xvfb-run -a python main.py` и отдельный сценарий прохода по вкладкам.

## Проверка восстановления v0.8.2

- F8 создаёт ручной снимок; F9 возвращает его, только если пользователь подтвердил замену мира.
- Проверьте сохранение/восстановление генома, ID и RNG в экосистеме, а также историю измерений.
- После штатного выхода Life должна предложить продолжить предыдущую сессию. При отказе автоматическая копия удаляется, ручная остаётся.
- Выключите автосохранение: автоматический файл должен исчезнуть, ручной — остаться.
- Смоделируйте отказ при записи: старый `.lifelab` не должен измениться.

Детали: [RECOVERY.md](RECOVERY.md).

## Проверка v0.9.0

1. Откройте мир и после 10–15 поколений откройте вкладку «События» в правой панели (F7).
2. Переключите чувствительность и группу событий: список должен пересчитаться, мир не должен измениться.
3. Проверьте подробности выбранной строки и экспорт CSV: номер поколения должен соответствовать наблюдению из исследовательского журнала.
4. Включите паузу при критических событиях, создайте мир с высокой начальной плотностью, запустите симуляцию. При резком сокращении автоматическое выполнение должно остановиться.
5. В 3D проверьте среднее, максимум и сумму для «Влага», «Плотность», «Глубина родословной». Значения по краю поля не должны усредняться с выдуманными нулями.
6. Запустите `python tools/benchmark_spatial.py` и зафиксируйте локальные медианные значения. Сравнивайте только при одинаковых параметрах и на одной машине.
7. Сохраните и загрузите старый мир: журнал измерений должен восстановиться, лента — пересчитаться без изменения RNG.

Тесты для логики этих функций: `tests/test_timeline_090.py`.


## Приёмка версии 1.0.0

Локально выполнено **166 автоматических тестов**, включая новые сценарии, пакет воспроизводимости, проверку SHA-256, DPI и защиту архивов. CI должен подтвердить результат отдельно. Проверки графического интерфейса под Linux проводятся через Xvfb; в Windows workflow открывается уже упакованная программа. Это не заменяет испытание на Windows 10/11.

1. `python main.py --smoke-test` проверяет работу файлов без окна.
2. `xvfb-run -a python main.py --ui-smoke-test ./ui-acceptance` (Linux) проверяет открытие графики, переключение в экосистему, план сценариев, график и отсутствие изменений исходной сессии. В отчёте будут фактическая ОС, DPI, Tk и разрешение; снимок интерфейса создаётся, когда доступны права захвата экрана.
3. Создать план с `Intervention(0, "moisture", 0)`: обе ветви должны дать идентичные матрицы, историю, RNG и происхождение животных.
4. Для плана «Засуха» проверить, что изменяется только опытная ветвь. В исходном мире сравнить клетки, поколение, RNG и родословные до и после.
5. Проверить некорректные события: NaN, бесконечность, неизвестный параметр, событие после окончания, климатическое событие при выключенной экологии.
6. Завершить опыт, выгрузить CSV/JSON и архив ZIP. Проверить ZIP: `python -m life_lab.scenarios архив.zip`, распаковать три `.lifelab` и открыть их в приложении.
7. Убедиться, что испорченный SHA или неизвестный путь в архиве сценария отклоняются. Проверить, что `storage.py` отклоняет NPZ с дублированными элементами и чрезмерно большими размерами.
8. Проверить интерфейс при 1366×768 и 1920×1080 с DPI 100/125/150; у приложения должны оставаться доступные кнопки и карта. Провести это отдельно на пользовательской Windows 10/11; Windows Server CI недостаточно.
9. После GitHub Actions проверить в релизе исходный ZIP и **Windows x64 ZIP**, `ui-report.json` в artifacts и фактический SHA опубликованного коммита.

Подробная методика — [SCENARIOS.md](SCENARIOS.md), [SECURITY.md](SECURITY.md) и [WINDOWS.md](WINDOWS.md).
