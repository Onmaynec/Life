# Восстановление сессии и контрольные точки

Начиная с Life v0.8.2 приложение сохраняет текущее состояние мира автоматически и позволяет отдельно закрепить одну контрольную точку. Это разные файлы: автоматическая копия обновляется примерно каждые три минуты, а ручная остаётся до следующего нажатия F8.

## Автосохранение

Автосохранение включено по умолчанию. Переключатель расположен в левой панели, раздел «Файлы». После нормального закрытия Life также сохраняет последнюю сессию. При следующем запуске приложение предложит восстановить её; если отказаться, автоматическая копия будет удалена. Это позволяет продолжить работу после завершения программы и снижает потери при аварийном закрытии.

Автосохранение не заменяет обычное сохранение проекта: для переносимой копии используйте «Сохранить» и файл `.lifelab` в выбранном каталоге. Интервал в три минуты — это верхняя оценка времени потерянной работы между периодическими копиями; при аварии возможна потеря изменений, внесённых после последней копии.

Если автосохранение отключить, существующая автоматическая копия удаляется. Ручная контрольная точка при этом сохраняется.

## Контрольные точки

- **F8 / «Снимок»** — закрепить текущее состояние в отдельном файле. Старый ручной снимок заменяется только после успешной записи нового.
- **F9 / «Вернуть»** — вернуться к последней ручной точке. Life попросит подтвердить замену текущего мира.
- Снимок содержит клетки, ресурсы, генетику, ID и родословные животных, состояние генератора случайных чисел, журнал поколений и исследовательскую историю.
- После восстановления симуляция остаётся на паузе. Это возвращение мира, а не отмена одного действия в редакторе.

## Где лежат файлы

| Система | Каталог |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Life\recovery` |
| Linux | `${XDG_STATE_HOME:-~/.local/state}/Life/recovery` |

`autosave.lifelab` — автоматическое восстановление. `checkpoint.lifelab` — закреплённая точка. Оба файла используют тот же формат 5, что обычные миры Life. Их можно открывать через «Открыть», но для штатного восстановления удобнее использовать предложение при запуске и F9.

## Защита от обрыва записи

Life записывает сохранение в отдельный временный файл в **том же каталоге**, синхронизирует его и только после этого заменяет целевой путь. Если запись не завершилась, прежний `.lifelab` остаётся без изменений, а временный файл удаляется. Этот подход защищает от частичной перезаписи при ошибке сохранения, но не гарантирует сохранность данных при неисправности диска или потере питания. Для важных исследований храните резервные копии за пределами одного накопителя.

При ошибке периодического автосохранения появляется сообщение в строке состояния. Если сохранить сессию не удалось при выходе, Life предложит отменить закрытие. При неудаче чтения предыдущего снимка программа оставляет файл на месте и сообщает об ошибке — повреждённый файл не удаляется автоматически.

## Проверка

1. Создайте мир и проведите несколько поколений; нажмите F8.
2. Проведите ещё несколько поколений, затем F9. Поколение, численность и история должны вернуться к состоянию снимка.
3. Дайте приложению создать автосохранение или закройте его штатно, затем запустите повторно. Выберите восстановление и проверьте мир.
4. Для проверки ошибки записи поместите старый файл в тестовый каталог и воспроизведите ошибку записи. Старый файл должен оставаться открываемым, а временный — удаляться.
5. Повторите действия для экосистемы с родословными и сохранения старой версии, открытого через обычное меню.

Автоматизированные проверки: `python -m unittest tests.test_recovery -v`. Отдельная ручная проверка на Windows 10/11 всё ещё нужна для системной рамки и масштабирования UI; добавление восстановления не закрывает эти задачи.
