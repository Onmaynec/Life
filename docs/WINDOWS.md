# Windows — выпуск, диагностика и приёмка

## Скачать и запустить

На странице [Releases](https://github.com/Onmaynec/Life/releases) есть исходный ZIP `Life-vX.Y.Z.zip`. Для запуска исходников нужен Python 3.10+ (в Windows можно открыть `START_WINDOWS.bat`).

Для версии 1.0.1 отдельно собирается архив **`Life-v1.0.1-Windows-x64.zip`**. Внутри лежит каталог `Life` с `Life.exe` и папкой `_internal`; извлечённый из пакета один `.exe` **не** является автономным. Файл прикрепляется к GitHub Release **только после успешных unit, engine и GUI smoke** на Windows Server 2022 CI. Если такого файла нет в Releases, значит автоматическая проверка/публикация ещё не закончена или не прошла.

Сборка из исходников на Windows с Python 3.12:

```powershell
python -m pip install -r requirements.txt 'pyinstaller>=6,<7'
python -m PyInstaller --noconfirm --clean --onedir --windowed --name Life --hidden-import matplotlib.backends.backend_tkagg --hidden-import mpl_toolkits.mplot3d main.py
.\dist\Life\Life.exe --smoke-test
.\dist\Life\Life.exe --ui-smoke-test .cceptance
```

Встроенная проверка `--smoke-test` работает без окна и проверяет создание мира, сохранение/загрузку, родословные, RLE, PNG, CSV, настройки и восстановление. `--ui-smoke-test` открывает Tk, запускает две независимые ветви Scenario Studio, проверяет сохранность исходной сессии, записывает `ui-report.json` и, если разрешён захват экрана, `scenario-studio.png`.

## Что проверяет CI и чего он не проверяет

Workflow `.github/workflows/windows-build.yml` выполняется на **Windows Server 2022**, не на пользовательской Windows 10/11. Успешный запуск пакета с GPU/GUI не подтверждает все сочетания ОС, видеодрайверов, антивирусов, системной темы и высокого DPI. CI включает упакованный UI smoke и сохраняет отчёт с точным именем ОС и разрешением экрана.

### Матрица ручной приёмки для Issues #5–#7

| Проверка | Windows 10 | Windows 11 |
| --- | --- | --- |
| Запуск Life.exe без установленного Python, из полного каталога | Требуется | Требуется |
| Открытие/сохранение `.lifelab`, восстановление F8/F9 | Требуется | Требуется |
| Импорт RLE и экспорт PNG/CSV/JSON | Требуется | Требуется |
| 1366×768 и 1920×1080, DPI 100%, 125%, 150% | Требуется | Требуется |
| Тёмный/светлый системный режим, DWM и кнопки окна | Требуется | Требуется |
| Alt+Tab, сворачивание, разворачивание, максимизация, F11 | Требуется | Требуется |
| ПКМ/СКМ, колесо, вкладки, Scenario Studio | Требуется | Требуется |

Для каждого прогона зафиксировать сборку/версию Windows (`winver`), разрешение, масштаб DPI, дату, исходный ZIP, результат, скриншоты при проблемах. Удалить личные данные из отчётов перед публикацией. Результат добавить в соответствующий Issue. **Ни один из этих пунктов нельзя отмечать как проведённый без реальной проверки**.

## Нативный заголовок

`life_lab/chrome.py` использует только поддерживаемый путь через DWM: пытается включить тёмный заголовок (атрибуты 20/19), установить цвет фона и текста (35/36) и оставляет системные кнопки Windows. Если атрибут недоступен или ОС отвергла вызов, Life продолжает работать со стандартной рамкой. На Linux эти вызовы не выполняются.

Для визуального теста требуется запустить именно графическую программу на пользовательской Windows; автоматические тесты функции DWM на Python не заменяют осмотр реального окна.
