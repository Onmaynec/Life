# Выпуск версии Life

1. Изучить изменения в `main`, связанные Issues и потенциальные несовместимости. Не выдавать запланированное за реализованное.
2. Обновить `life_lab/__init__.py` и добавить полный раздел версии в `CHANGELOG.md` с конкретными изменениями. Обновить README, документы и тесты.
3. Прогнать локальные проверки:

```bash
python -m unittest discover -s tests -v
python main.py --smoke-test
# На Linux при наличии Xvfb:
xvfb-run -a python main.py --ui-smoke-test ./ui-report
```

4. Внести изменения в `main` одним непротиворечивым коммитом. Не переписывать опубликованные теги, не применять force push. Если параллельно кто-то внёс изменения, сначала перепроверить текущее состояние ветки.
5. `.github/workflows/tests.yml` запускает unit и smoke на поддерживаемых версиях Python. `.github/workflows/release.yml` дополнительно проверяет версию, создаёт тег и исходный `Life-vX.Y.Z.zip` при новом номере версии. Существующий тег не перезаписывается.
6. `.github/workflows/windows-build.yml` собирает пакет на Windows Server 2022, проверяет **упакованный** `Life.exe --smoke-test` и `--ui-smoke-test`, прикладывает отчёт. Только после прохождения проверок архив `Life-vX.Y.Z-Windows-x64.zip` автоматически добавляется в существующий релиз.
7. Проверить фактическое наличие обоих файлов в Releases, статусы workflows и список открытых Issues. Закрывать задачу только после выполнения исходных критериев приёмки; автоматизированная проверка Windows Server не подменяет ручную проверку Windows 10/11.

Проверка целостности архивов сценариев: `python -m life_lab.scenarios исследование.zip`. Порядок ручной Windows-приёмки: [WINDOWS.md](WINDOWS.md).
