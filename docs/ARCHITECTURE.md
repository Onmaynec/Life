# Как устроена симуляция

Приложение состоит из интерфейса на Tkinter и двух независимых моделей, которые обновляются вручную через `step()`. Интерфейс не должен отвечать за правила мира.

## Классический режим

`CellularAutomaton` хранит двумерный массив `uint8`. При каждом шаге подсчитываются восемь соседей каждой клетки, затем по выбранному правилу B/S одновременно создаётся новое поколение. Параметр `wrap` разрешает переход через границы.

## Экосистема

`Ecosystem` хранит карты типов клеток, энергии, питательных веществ и наследуемых признаков. Питательные вещества восстанавливаются постепенно. Растения растут на подходящей почве. Животные обновляются в случайном порядке: вначале хищники, затем травоядные. В каждом поколении животное расходует энергию, пытается добыть пищу, перемещается и при достаточном запасе энергии может оставить потомка. Это локальная модель; она не имитирует молекулярную биологию.

Внутри мира используется собственный генератор случайных чисел NumPy. Его состояние сохраняется вместе с миром, поэтому в рамках одной версии программы можно повторить дальнейшие шаги после загрузки.

## Файлы

`.lifelab` — сжатый NPZ-контейнер. Массивы хранятся отдельно, а настройки и счётчики — в JSON-метаданных внутри контейнера. При чтении запрещена загрузка pickle; размеры и типы содержимого проверяются до восстановления состояния.

`patterns.py` содержит RLE-конвертер для обычной игры Конвея. Его нельзя использовать для сериализации экосистемы, потому что RLE не содержит энергию и наследуемые признаки.


## Настройка мира и журнал измерений (v0.3.0)

`setup.py` проверяет параметры в `WorldOptions` и создаёт экземпляр классического мира либо экосистемы. Для экосистемы начальная доля каждого вида задаётся в процентах от площади. Один seed используется для начальной популяции и почвы, поэтому эксперименты воспроизводимы.

`history.py` собирает статистику после каждого шага. Численность и средние значения генов записываются отдельно для травоядных и хищников; для отсутствующего вида среднее — `None`, а в CSV это пустая ячейка. Хранятся последние 10 000 строк; панель рисует последние 120.

`storage.py` пишет историю вместе с миром в формат `.lifelab` версии 3. Загрузка версий 1 и 2 сохранена: при их открытии журнал создаётся с одной начальной строкой, соответствующей поколению загруженного мира. `load_world` остаётся доступным старым клиентам, а интерфейс использует `load_document` для чтения мира с историей.


## Отрисовка и настройки интерфейса (v0.4.0)

`visuals.py` содержит три палитры и отрисовку фрагмента поля через NumPy и Pillow. Интерфейс передаёт в `draw_view` только видимую часть массивов, масштаб и выбранный стиль. При достаточно крупном масштабе используется слой фигур с мягким светом или плитки; при малом масштабе остаётся простой вид. Функция не изменяет массивы мира и не влияет на ход симуляции.

`app.py` отвечает за расположение панелей, рисование кадра, навигатор и графики. Мини-карта уменьшает полное поле до доступного размера; рамка показывает положение камеры. Инспектор считывает данные клетки только по текущим координатам курсора и не меняет состояние мира. PNG-экспорт использует ту же функцию `draw_view`, что и рабочее поле.

`preferences.py` хранит только настройки внешнего вида и скорости в JSON: на Windows — в `%APPDATA%/Life/preferences.json`, на Linux — в `${XDG_CONFIG_HOME:-~/.config}/Life/preferences.json`. Отсутствующий или повреждённый файл заменяется безопасными настройками по умолчанию. Эти параметры намеренно не включены в `.lifelab`: совместимость файлов миров и воспроизводимость эксперимента не зависят от оформления.

## Расширение модели и исследовательские вкладки (v0.5.0)

`ecology.py` описывает `EcologySettings`, климатические индексы, движение воды и минералов, последовательность дополнительных взаимодействий растений и животных. Дополнительные правила отключены по умолчанию для прямого API `Ecosystem()`, чтобы исходные расчёты и сохранения v1–v3 не менялись неявно. При создании экосистемы через UI эти правила включаются. Новые состояния хранятся в отдельных двумерных массивах той же формы, что и `cells`: `age`, `moisture`, `seeds`, `organic`, `toxins`, `altitude`. При перемещении животных возраст переносится вместе с организмом.

`instruments.py` делает чтение матриц, считает независимые показатели и содержит ограниченный журнал `ResearchLog`. Тяжёлые кластеры в истории пересчитываются раз в пять шагов; в промежуточных поколениях они отмечаются как не измеренные, а не копируются из предыдущего замера. Подсчёт компонент учитывает обычные и тороидальные границы. `spatial_field` усредняет данные блоками перед 3D-отрисовкой; интерпретация 3D как нового пространства физического мира недопустима.

`research_ui.py` содержит вкладки исследовательского интерфейса, настройки экосистемы, графики и каталог. 3D-предпросмотр и полноразмерное окно вынесены в `research_3d.py`; контроллер вкладок подключает его через небольшой mixin. `editor_history.py` хранит независимые снимки редактора, включая правило B/S и родословную. Курсор рисуется отдельным слоем Canvas, поэтому его движение не перестраивает изображение мира. `skins.py` задаёт нейтральные поверхности и цветовые акценты. `chrome.py` включает нативное оформление системного заголовка Windows через DWM с проверкой доступности API; на остальных платформах это no-op. В `visuals.py` появились 2D количественные слои.

`storage.py` сохраняет формат 5: прежние поля, дополнительные массивы среды, исследовательский журнал и родословную. При загрузке числовые слои проверяются по форме, типу, конечности и диапазону до приведения к целевому dtype. Для форматов 1–4 сохранена миграция; отсутствующие поля инициализируются безопасно. Состояние RNG продолжает сохраняться. `load_document` и `load_world` сохраняют старые сигнатуры; журнал расширенных измерений читается через `load_research`.

Климатические правила и приборы относятся к *синтетической* среде. Надёжность их проверяется на детерминизм, диапазоны, чтение сохранений и отсутствие мутаций при измерении; биологическая достоверность не утверждается.


## Серии экспериментов (v0.6.0)

`life_lab/experiment_suite.py` не зависит от Tkinter. `ExperimentPlan` валидирует границы параметров, размеры и размер пакета; `ExperimentSession` последовательно создаёт независимые миры. `advance()` выполняет не больше одного поколения, записывает контрольные точки и отдаёт агрегаты после завершения каждого запуска. `run_experiment()` — синхронная обёртка для скриптов и тестов.

В `life_lab/experiment_ui.py` размещён отдельный графический контроллер `ExperimentStudio`. Он запускает симуляции небольшими частями через `Tk.after`, показывает прогресс, графики и результаты. Главное приложение владеет только ссылкой на окно. UI не получает ссылку на активный мир для изменения: для опытов используется новый экземпляр или глубокая копия состояния. Данные серии не входят в `.lifelab`; экспорт выполняется в отдельные CSV/JSON/MD.

## Учёт происхождения (v0.7.0)

`life_lab/lineage.py` содержит `Pedigree` — матрицу стабильных ID и записи предков. `world.Ecosystem` вызывает его при создании, движении, размножении и смерти животных. `ecology.environmental_step` синхронизирует ID с миграцией и смертностью от среды. `storage.py` сохраняет ID в `animal_ids`, а реестр — в метаданных версии 5. Старые миры получают новых основателей при загрузке. `research_ui.py` показывает родословные, а `instruments.py` измеряет их распределение. Обработка не потребляет дополнительные случайные числа.


## Визуальные инструменты (v0.8.0)

Отрисовка остаётся в `visuals.py` и принимает только копии видимых фрагментов массивов через срезы. Новые стили «Неон», «Контуры» и «Созвездие» используют Pillow; неоновые спрайты кэшируются по масштабу, типу клетки и палитре. При малом масштабе выполняется пиксельная отрисовка без отдельных фигур. В `skins.py` заданы отдельные цветовые схемы UI: смена темы не касается модели.

`plotting.py` вычисляет линии без потери исходной оси поколений, проверяет нечисловые значения и отделяет промежутки без наблюдений. Интерфейс рисует линии, маркеры и заливку на Tk Canvas. При наведении выбирается ближайшая запись из последней истории; это чтение, не изменение данных. Координатная шкала и полоса состава популяции также создаются только из текущего состояния и не сохраняются в `.lifelab`.

Боковые панели упаковываются и скрываются без уничтожения виджетов; кнопки F6/F7 управляют ими отдельно. Переключение темы пересоздаёт оформление, сохраняя модель мира. `preferences.py` хранит `overlay` и `chart_fill`, сохраняя прежние значения при чтении старых настроек. Подробнее: [VISUALS.md](VISUALS.md).

## Контрольные точки и защита сохранений (v0.8.2)

`recovery.py` управляет отдельным каталогом локального состояния. Автоматический и ручной снимки используют обычный сериализатор `storage.py` и не меняют правила мира. При загрузке Life сначала проверяет весь документ и журнал исследований и только потом обновляет состояние UI. `storage.save_world()` формирует архив во временном файле в той же директории и заменяет предыдущий после успешной записи с `fsync`. См. [RECOVERY.md](RECOVERY.md).

## Лента событий и пространственная выборка (v0.9.0)

`timeline.py` — чистые функции, получающие соседние записи `ResearchLog`: пороговые наблюдения, фильтрация неизвестных чисел и экспорт CSV. Они не читают `Ecosystem` и не потребляют RNG. В `research_ui.py` находится седьмая вкладка, в `app._advance()` — только опциональная остановка при новом критическом наблюдении. События заново выводятся из журнала, поэтому формат сохранения мира не менялся.

`instruments.spatial_field()` выбирает исходный массив только для запрошенного слоя, а затем использует `np.add.reduceat`/`np.maximum.reduceat`; для среднего учитывается фактический размер крайних блоков. Временные массивы не меняют мир. Сохранены три исходные агрегации; сравнение с предыдущей реализацией проверяется регрессионными тестами.


## Парные сценарии и релиз 1.0.0

`scenarios.py` — самостоятельный модуль без GUI. `ScenarioSession` создаёт **три** независимые копии начального `Ecosystem`: эталон старта и две развивающиеся ветви. При каждом `advance()` воздействие применяется только к экспериментальному миру до очередного шага, затем оба мира делают ровно один шаг; наблюдения записываются в заданном интервале и на последнем шаге. Управление RNG остаётся внутри копий миров — глобальные источники случайности не используются. План проверяет тип, конечность и диапазон каждого параметра, включая допустимость климатических событий при выключенном модуле экологии.

`scenario_ui.py` содержит отдельное неблокирующее окно Tk: редактор плана, запуск, паузу, график контроля/воздействия и экспорт. Главное приложение вызывает его по `Ctrl+Shift+E` и не передаёт управление своим циклом симуляции. При смене темы дочернее окно закрывается, а текущая сессия остаётся неизменной.

В ZIP-архиве опыта хранятся три открываемых `.lifelab`, `measurements.csv`, `report.json` и `manifest.json` с SHA-256. `verify_bundle()` проверяет имена, суммарный размер и хеши без извлечения произвольных путей. `.lifelab` дополнительно проходит проверку размеров и числа ZIP-элементов в `storage.py` до загрузки NumPy.

`layout.py` измеряет ширину для переключения компоновки в логических 96-DPI пикселях. На экранах с высоким масштабированием панели скрываются раньше, но сами размеры основных данных не меняются. `ui_smoke.py` реализует тест запуска Tk и Scenario Studio, применимый также к PyInstaller-сборке через `main.py --ui-smoke-test`.
