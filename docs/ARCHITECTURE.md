# Как устроена симуляция

Приложение состоит из интерфейса на Tkinter и двух независимых моделей, которые обновляются вручную через `step()`. Интерфейс не должен отвечать за правила мира.

## Классический режим

`CellularAutomaton` хранит двумерный массив `uint8`. При каждом шаге подсчитываются восемь соседей каждой клетки, затем по выбранному правилу B/S одновременно создаётся новое поколение. Параметр `wrap` разрешает переход через границы.

## Экосистема

`Ecosystem` хранит карты типов клеток, энергии, питательных веществ и наследуемых признаков. Питательные вещества восстанавливаются постепенно. Растения растут на подходящей почве. Животные обновляются в случайном порядке: вначале хищники, затем травоядные. В каждом поколении животное расходует энергию, пытается добыть пищу, перемещается и при достаточном запасе энергии может оставить потомка. Это локальная модель; она не имитирует молекулярную биологию.

Внутри мира используется собственный генератор случайных чисел NumPy. Его состояние сохраняется вместе с миром, поэтому в рамках одной версии программы можно повторить дальнейшие шаги после загрузки.

## Файлы

`.lifelab` — сжатый NPZ-контейнер. Массивы хранятся отдельно, а настройки и счётчики — в JSON-метаданных внутри контейнера. При чтении запрещена загрузка pickle; размеры и типы содержимого проверяются до восстановления состояния.

`patterns.py` содержит RLE-конвертер для обычной игры Конвея. Его нельзя использовать для сериализации экосистемы, потому что RLE не содержит энергию и наследуемые признаки.


## Настройка мира и журнал измерений (v0.3.0)

`setup.py` проверяет параметры в `WorldOptions` и создаёт экземпляр классического мира либо экосистемы. Для экосистемы начальная доля каждого вида задаётся в процентах от площади. Один seed используется для начальной популяции и почвы, поэтому эксперименты воспроизводимы.

`history.py` собирает статистику после каждого шага. Численность и средние значения генов записываются отдельно для травоядных и хищников; для отсутствующего вида среднее — `None`, а в CSV это пустая ячейка. Хранятся последние 10 000 строк; панель рисует последние 120.

`storage.py` пишет историю вместе с миром в формат `.lifelab` версии 3. Загрузка версий 1 и 2 сохранена: при их открытии журнал создаётся с одной начальной строкой, соответствующей поколению загруженного мира. `load_world` остаётся доступным старым клиентам, а интерфейс использует `load_document` для чтения мира с историей.


## Отрисовка и настройки интерфейса (v0.4.0)

`visuals.py` содержит три палитры и отрисовку фрагмента поля через NumPy и Pillow. Интерфейс передаёт в `draw_view` только видимую часть массивов, масштаб и выбранный стиль. При достаточно крупном масштабе используется слой фигур с мягким светом или плитки; при малом масштабе остаётся простой вид. Функция не изменяет массивы мира и не влияет на ход симуляции.

`app.py` отвечает за расположение панелей, рисование кадра, навигатор и графики. Мини-карта уменьшает полное поле до доступного размера; рамка показывает положение камеры. Инспектор считывает данные клетки только по текущим координатам курсора и не меняет состояние мира. PNG-экспорт использует ту же функцию `draw_view`, что и рабочее поле.

`preferences.py` хранит только настройки внешнего вида и скорости в JSON: на Windows — в `%APPDATA%/Life/preferences.json`, на Linux — в `${XDG_CONFIG_HOME:-~/.config}/Life/preferences.json`. Отсутствующий или повреждённый файл заменяется безопасными настройками по умолчанию. Эти параметры намеренно не включены в `.lifelab`: совместимость файлов миров и воспроизводимость эксперимента не зависят от оформления.

## Расширение модели и исследовательские вкладки (v0.5.0)

`ecology.py` описывает `EcologySettings`, климатические индексы, движение воды и минералов, последовательность дополнительных взаимодействий растений и животных. Дополнительные правила отключены по умолчанию для прямого API `Ecosystem()`, чтобы исходные расчёты и сохранения v1–v3 не менялись неявно. При создании экосистемы через UI эти правила включаются. Новые состояния хранятся в отдельных двумерных массивах той же формы, что и `cells`: `age`, `moisture`, `seeds`, `organic`, `toxins`, `altitude`. При перемещении животных возраст переносится вместе с организмом.

`instruments.py` делает чтение матриц, считает независимые показатели и содержит ограниченный журнал `ResearchLog`. Тяжёлые кластеры в истории пересчитываются раз в пять шагов; при ручном просмотре получают актуальное значение. `spatial_field` усредняет данные блоками перед 3D-отрисовкой; интерпретация 3D как нового пространства физического мира недопустима.

`research_ui.py` содержит вкладки исследовательского интерфейса, настройки экосистемы, графики, 3D-окно и каталог. `skins.py` задаёт нейтральные поверхности и цветовые акценты. `chrome.py` включает нативное оформление системного заголовка Windows через DWM с проверкой доступности API; на остальных платформах это no-op. В `visuals.py` появились 2D количественные слои.

`storage.py` сохраняет формат 4: прежние поля, дополнительные массивы среды и, если журнал доступен, `research`. Для форматов 1–3 дополнительные правила выключены; значения отсутствующих полей инициализируются безопасно. Состояние RNG продолжает сохраняться. `load_document` и `load_world` сохраняют старые сигнатуры; журнал расширенных измерений читается через `load_research`.

Климатические правила и приборы относятся к *синтетической* среде. Надёжность их проверяется на детерминизм, диапазоны, чтение сохранений и отсутствие мутаций при измерении; биологическая достоверность не утверждается.
